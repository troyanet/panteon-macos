# Протокол подсветки — заметки (Sinowealth 320F)

## Наше устройство
- «RGB Keyboard», VID `0x320F` (Sinowealth), PID `0x5080`, **USB Vendor = "Evision"**, bcdDevice 1.00.
- Физически: PANTEON, TKL (~87 клавиш, ретро/печатная машинка, ролик громкости, проводная). Модель на корпусе не указана. PANTEON = ребренд Evision → протокол тот же, что у семейства Evision/Sinowealth (см. AK820 `505B`).
- Служебный канал: HID UsagePage **`0xFF00`**, Feature report до **132** байт.

## Ближайший известный аналог: Ajazz/Evision AK820 — `320F:505B`
Источник: реверс-драйвер `Serjik-Developer/ak820-linux-driver` + его Issue #1. Протокол снят из Windows-софта через USBPcap.

- У AK820 служебный канал — UsagePage **`0xFF1C`**, пакеты **64** байта, `report_id = 0x04`.
- **Рабочий («официальный») диалект:** кадр `0x06`, payload начинается со смещения 7:
  - `[2]` = mode, `[3]` = brightness, `[4]` = speed, `[5..6]` = `FF 00`, `[7,8,9]` = R,G,B.
- **OpenRGB-диалект (кадр 0x06 с хвостом `[mode,brightness,speed,dir,rnd,r,g,b]` c байта 8) этой прошивкой ИГНОРИРУЕТСЯ** — клавиатура эхо-отвечает, но подсветку не меняет.
- Таблица режимов `0x00..0x14`: `0x01`=off, `0x05`=breathing, `0x06`=static all, `0x07`=reactive, `0x11`=static shifting hue, `0x14`=custom per-key и т.д.
- **Brightness: 0..4** (0=off; значение 5 невалидно, хотя в коде был MAX=5). **Speed: 0..5** (0=быстрее всего).
- **Custom per-key:** таблица 128 RGB-слотов в памяти по offset `0x0400`.
- **Обязательный фикс:** после КАЖДОЙ записи читать ответ (drain reply), иначе управляющий канал подвисает и клавиши перестают работать до переподключения.

## Родной софт PANTEON T20 PRO (статический разбор, без запуска)
Файл: `Panteon_T20_PRO.exe` (NSIS installer) → `app.7z` → приложение. SHA256 инсталлятора: `7481784f…a7151`.

- Главный бинарник: `PANTEON T20 PRO.exe` — нативный C++ (DuiLib UI). Классы: `CEevisionKeyboardDevice`, `CEevisionUSBDevice`, `CEevisionHS6533Device`, `CEevisionMouseDevice`, `CEevisionMousePadDevice` → подтверждает Evision.
- **Транспорт: `HidD_SetOutputReport`** (команды идут Output-репортом; + `HidP_GetUsageValue`). Прим.: у AK820 был report через 0xFF1C; у нас служебный канал 0xFF00 — сверить при декомпиляции.
- **Таблица режимов клавиатуры (`DefaultData/default_light.json`, это и есть байт `mode`):**
  0=wave(скрыт),1=wave,2=cloud,3=vortex,4=mix_color,5=breath,6=static,7=reaction,8=stone,9=traverse,10=stars,11=firework,12=roll,13=wave_bar,14=cartoon,15=rain,16=scan,17=zzcc,18=speed,19/20=custom,21=reaction,24=off,25=zzcc,28=audiorecord,29=capturecolor,30=wave. (Отдельные таблицы для мыши/др. устройств.)
- Цвет: ARGB hex (напр. `FFFF0000`). Палитра по умолчанию — `color_option_info.config`.
- Custom per-key: `DefaultData/Keyboard.json` → `CustomLightMode.LightColorInfo` = массив по клавишам {Alpha,Red,Green,Blue}.
- Данные устройства/звука: `HD.Json` (EQ) — к подсветке не относится.

**Не хватает для безопасной записи:** точный байтовый layout Output-репорта (report ID, длина, позиции mode/speed/brightness/direction/color, контрольные байты). Лежит в коде `PANTEON T20 PRO.exe` вокруг `HidD_SetOutputReport` → нужна декомпиляция (Ghidra).

## Декомпиляция родного софта (Ghidra) — формат пакета подсветки
Полная декомпиляция вызывающих HID-функций: `docs/decomp-hid-callers.txt`. Ключевая функция — `FUN_00485fd0` @ `0x485fd0` (отправка кастомной/per-key подсветки).

- **Транспорт:** `HidD_SetOutputReport(hidHandle, buf, 0x11)` — Output report, **длина 17 байт**.
- **HID-хэндл** хранится в объекте устройства по offset `+0x8B4`.
- **Структура буфера (17 байт):**
  - `[0]` = `0xFF` — report ID.
  - `[1..2]` = 16-битный **заголовок блока** (little-endian): `0xAA22`, затем `0xAA44`, `0xAB22`, `0xAB44`, `0xAC22`, `0xAC44` (блоки R/G/B по зонам) и варианты `0xAD..`, `0xAE..`, `0xAF..`.
  - `[3]` = ещё байт заголовка (0 по умолчанию).
  - `[4..]` = данные цвета по клавишам: по 7 байт (abStack_44 = канал 1, abStack_34 = канал 2, abStack_24 = канал 3) либо по 6 байт (auStack_* — продолжение зоны).
- **Яркость:** каждый канал = `(raw * factor) >> 8`, с жёстким кэпом **`0xF7` (247)** — потолок значения канала (НЕ 255).
- Полный кадр per-key = серия из ~12 таких 17-байтовых отчётов (по зонам LED).

**Осталось для простого управления (static/breath + один цвет + яркость):** найти функцию установки РЕЖИМА (mode/brightness/speed/color одним пакетом) — скорее всего рядом, через те же `HidD_SetOutputReport`/`FUN_004b5720`. Таблица `mode` уже известна (см. выше).

## Командный протокол (64 байта) — ВОССТАНОВЛЕН
Отдельный канал от per-key. Отправка: `FUN_00477500(buf, 0x40, resp, 0x40, ...)` → `FUN_004b5720` → async `WriteFile` на HID-хэндл по offset `+0x1c` (64 байта команда + 64 байта ответ). Декомпиляции: `docs/decomp-command-builders.txt`, `docs/decomp-transport.txt`.

**Формат 64-байтного пакета:**
- `[0]` = **opcode** (у всех set-команд = `4`).
- `[1..2]` = **контрольная сумма** = сумма байтов `[3..63]`, little-endian (`[1]`=low, `[2]`=high). ❗Без неё команда невалидна.
- `[3]` = **субкоманда** (что настраиваем).
- `[4..]` = параметры.
- остальное до 64 — нули.

**Субкоманды (`[3]`) — это операции чтения/записи блоков памяти устройства:**
- Общий вид R/W-команды: `[4]`=длина куска (chunk ≤ `0x38`=56), `[5..6]`=адрес/offset в памяти устройства (LE), `[8..]`=данные (для записи). Большие структуры льются циклом по кускам.
- Встречены: `5`,`6`,`0x0A`,`0x0B`,`0x17`,`0x1A` — R/W разных областей (цвета/эффекты/настройки); `1`,`2`,`7`,`9`,`0x12`,`0x15`,`0x1B`,`0x1C` — короткие команды; `0xAA` — query (FUN_0047a620, без параметров, безопасна).
- **Вывод:** управление подсветкой = прочитать конфиг-блок (read-субкоманда) → поменять поля (режим/яркость/цвет) → залить обратно (write-субкоманда) с верной контрольной суммой. Раскладка полей внутри блока (где mode/brightness/RGB) — следующий шаг: сопоставить `DefaultData/*.json` ↔ байты реально прочитанного блока (read неразрушающий).

**Пример безопасной query-команды (FUN_0047a620):** `[0]=4, [3]=0xAA, [4..7]=0`, checksum в `[1..2]`. Ответ 64 байта — удобно для первого НЕразрушающего теста связи.

## Два канала — итог
1. **Команды** (режим/яркость/настройки): 64 байта, opcode+checksum+субкоманда, HID `+0x1c`.
2. **Per-key RGB**: 17 байт, report `0xFF`, заголовки `0xAAxx..0xACxx`, HID `+0x8B4`, кэп канала `0xF7`.

## ⚠️ Риск окирпичивания (важно)
- OpenRGB **отключил** общий Sinowealth keyboard-контроллер из-за **окирпичивания** некоторых Redragon-клавиатур: разные модели переиспользуют VID/PID, и чужой протокол пишется «не туда».
- Наш `5080` отличается от `505B`: другая UsagePage (`FF00` vs `FF1C`), другой размер report (132 vs 64). **Слепо писать протокол AK820 в нашу клавиатуру нельзя** — риск реальный.

## Безопасный путь к точному протоколу
1. **Лучший:** снять USB-дамп родного Windows-софта PANTEON (USBPcap/Wireshark на Windows) при смене режима/цвета/яркости — получим точные байты именно для `5080`.
2. Если Windows/софта нет — реверсить осторожно, начиная с чтения (Feature report GET), и пробовать по одному кадру, всегда готовыми к переподключению; но риск остаётся.
